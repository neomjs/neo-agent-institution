## Next: Fleet Manager v1 — an outside operator runs their own institution

Every walkthrough of the cockpit so far had the team as its user: the operator who built the plane, peers who know which button is wired. v1 is the first cut whose bar is someone else — an operator who downloads or forks, follows one supported path, and meets a real institution without maintainer folklore. The gate is behaviour we can observe, **on the installed candidate, end to end**:

> **On a supported first-run profile, an outside operator reaches a real connected institution; every surface reads its state truthfully — cold · live · stale · degraded · unreachable, each with its reason and a next step; the Observatory shows what the team has done and where attention goes, and opens a selected node's source; one representative engineering workflow runs through the cockpit with its context persisted, its review visible and its merge human; and an ordinary supported failure is recovered by following only the product's own guidance.**

[Milestone #1 — FM v1](https://github.com/neomjs/neo-agent-institution/milestone/1) is the tracking milestone; its linked items are the full set. This file names the gate and the load-bearing journeys, never the item list.

**Accounting — three rules.** A merged PR closes an implementation issue and **never retires an installed check**: a row passes when its walkthrough on the installed candidate passes, with a receipt. Every row carries one state — `unknown` (no installed check yet) · `blocked` (a named blocker) · `failed` (checked on a candidate, failed, receipt) · `passed` (candidate/installed version, engine and Brain pins, profile, evidence link). A row's scope changes only with a dated reason in this file — the denominator never improves by silently dropping a failure.

**The first decision — the supported first-run profile.** [D#18965](https://github.com/neomjs/neo/discussions/18965) separates *connect to an existing Brain* from *provision one*, and places the plane, the harness and workspaces, and inference as three separate declarations. The gate needs one declared profile per journey; the Discussion decides it, this file records it. **State: open.** The steward's recommendation: v1's supported profile is **connect** — the packaged vessel (or the served cockpit) attaches to an existing plane with the operator's own GitHub PAT, the path the team's plane already exercises (plane-attach, the stored plane record, bearer custody); *provision* — Docker plus an OpenAI-compatible endpoint, per the Brain's [SharedDeployment guide](https://github.com/neomjs/neo-agent-brain/blob/dev/learn/agentos/SharedDeployment.md) — stays the documented advanced route, with its host requirements declared, until it has an installed witness of its own. A connecting operator's machine must never inherit the server's Docker or GPU requirements by accident. Falsifier: if no outside operator has a plane to connect to, connect-first defers the hardest step to nobody, and the provision route must join the gate before v1.

**The load-bearing path — five journeys.** Stewards are the live assignees; an unstewarded row is an open option, never a pre-assignment. The done signal is the installed check; the state cell carries its date and receipt.

**How it runs.** Installed checks happen in bounded walkthrough sessions on a named candidate — version, engine and Brain pins, profile — with automated checks wherever they meet the criterion and eyes only where the criterion needs judgment; each session's pass · fail · blocked outcomes update the rows with the date and the receipt. Any peer claims subs; the steward owns the row's outcome and closes its epic. The engine's steady-state cadence is not this line's measure: v1 is the first cut, and its measure is the five rows reaching `passed` on one installed candidate. The cut itself — version, tag, the vessel's packaged build — is recorded when it is prepared; this file names the gate, not the date.

**Deferred — explicitly off the v1 path** (deferred is not rejected):

- **Automatic updates of the installed vessel** (the signed-feed item under [#7](https://github.com/neomjs/neo-agent-institution/issues/7)): v1 ships the documented manual update; a signed release feed is its own decision.
- **The Sharing pane** ([#16](https://github.com/neomjs/neo-agent-institution/issues/16)) and **the harness demotion** ([#17](https://github.com/neomjs/neo-agent-institution/issues/17)): grant families and supervision boundaries are product depth past the outside operator's first workflow.
- **The release video** ([#19](https://github.com/neomjs/neo-agent-institution/issues/19)): follows the gate; its footage comes from the installed walkthroughs.
- **View-layer conformance and design conformance** ([#24](https://github.com/neomjs/neo-agent-institution/issues/24), [#13](https://github.com/neomjs/neo-agent-institution/issues/13)) and **the debt matrix** ([#42](https://github.com/neomjs/neo-agent-institution/issues/42)): hygiene under the product surface — they land as leaves when a journey needs them, never as a gate.
- **The Observatory's live attribution half** (D#19317's OQ-W8, `[DEFERRED_WITH_TIMELINE]` on [#312](https://github.com/neomjs/neo-agent-institution/issues/312)) and **source views for node kinds beyond canonical GitHub ids and session ids**: v1's panel opens the kinds that have a source.
- **The provision route as a gated journey**: documented with its requirements, gated only once it has an installed witness (the profile decision above).
- **Cockpit-authored Neo apps and conversational UIs** ([D#18940](https://github.com/neomjs/neo/discussions/18940)) and **docking choreography beyond what the journeys use**: the engine line's showcase, consumed here when a journey asks for it.

**Session intake** for peers and contributors: read the gate, then [milestone #1](https://github.com/neomjs/neo-agent-institution/milestone/1) for the live set and the row's epic for the work. Work that serves a journey attaches under that row's epic as a one-PR leaf; work that serves none waits for the next line or joins the deferred set with its reason.
