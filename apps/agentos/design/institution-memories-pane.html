The memories pane — the operator's Memory Core access

The capability inventory came first (operator direction, 2026-08-28): the Memory Core already ships semantic search (query_summaries / query_raw_memories, with relevance scores), time-grain bird views (explore_memory_history: daily · 3-day · weekly · monthly · quarterly, per-identity or unified), per-turn mini-summaries with a literal short↔full API toggle (detail: 'summary' | 'full'), and hybrid GraphRAG (query_hybrid_graph) for the structural topology around a selected record. The pane is therefore not a list viewer — it is the operator's access to those instruments, in four registers: search · bird view · browse · drill. Everything below maps to a live MC operation; the fleet-source exposure gaps are declared in the capability table, never papered over.

No paging chrome (operator direction, 2026-08-28): paging buttons are an artifact of the hand-rolled offset windows — the buffered grid.Container destination scrolls, and the total ("3 sessions") belongs to the pane-head subtitle, not a footer strip. Precisely separated: bufferRowRange only bounds and recycles the MOUNTED rows over the locally loaded collection — it fetches nothing. Data acquisition is a controller-owned scroll-edge contract: one in-flight request at a time against the pane's target (session + page), page-echo validation before append, duplicate-request suppression, an honest loading tail while a page streams in (Loading memories…), an error state with retry when a page fails, and silence once the corpus end is reached. The engine-side generalization of that seam is neomjs/neo#17835 (scroll-edge on-demand loading for buffered grid + list); until it lands, the pane's controller owns the trigger.

The complete user-facing state family — and nothing else: populated · Loading memories… (the scroll contract's honest tail wears the same words) · No memories yet. (a fresh resident) · Couldn't load memories + retry. Four states a person can act on. The writer contract guarantees every STORED memory is complete (server-generated sessionId/timestamp, validated prompt/thought/response) — so no "unknown / unobserved / partial" class exists to design, and a malformed payload fails at the adapter/model boundary and materializes no row.

The hierarchy in one sentence: the title is the only weighted line and the recency band is the outer skeleton; kind is a closed-set chip over the add-summary vocabulary with a neutral mark on every value — the chip consumes T2 GEOMETRY only; --fm-kind-* is a closed family owned by activity-event kinds and is not borrowed (a memory-category token family would be its own explicit design decision); quality/impact/count stay honest mono facts (no meters — a bar would decorate what the number already says); co-authors compress to monogram marks with the full identities on title.

Provenance grammar (the two-level distinction the models already carry): summary cards wear derived (pill, quiet) — the Dream pipeline wrote them; drill rows wear authored once in the drill head — the resident wrote them. The response is the authored row's primary line (the pane's existing ruling, kept), prompt demotes to one detail line, amountToolCalls stays a micro fact.

The retrieval-hint affordance (#20's named element): an affordance-class chip per card — activating it copies the card's query_raw_memories("…") form (derived view-locally from title/session — clipboard is a view capability, no adapter change) so an operator or agent can jump from the browser into Memory Core recall. The exact query rides the button title; a card with no derivable hint renders no chip (exception logic, T2).

Implementation destination + interaction (#24 law 0 · law 1): the summary level is a custom-styled Neo.grid.Container (the primitive map names memories with the mailbox surfaces), law-1 name AgentOS.view.fleet.memories.Grid; recency bands are section rows, cards are the row design. Selection/focus/keyboard are grid-owned; the existing drill-in (open/back, INTENT-shaped) keeps its mechanics as row→detail — read-only throughout, nothing writes to the corpus from this surface. Depth chrome (`more`, prev/next) retires with the offset windows: `bufferRowRange` + scroll-edge loading replace it on both levels.
