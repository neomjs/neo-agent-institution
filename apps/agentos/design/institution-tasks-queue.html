Tasks pane — the orchestrator's heavy-maintenance queue

The pane that already answers WHAT the deployment is doing gains the rows the plane was missing on 2026-09-04: every starved waiter behind the maintenance lease, the lease itself as a fact, the backup lane. Same three sections, same row grammar [time] [name] [state] [progress?] [provenance], one more cell — the wait, as text. Rules from the peer input on #113 (Euclid, Emmy): the wait is unclamped text and never a progress kind; the state word is starved, never wedged; the lease is a summary fact with its observation time and no "since"; screen facts move only on a new watchdog stamp; the row cap stays per section with display priority labeled as such.

v2 (2026-09-05), after Euclid's review. Frame 1's causes come from the population the admission path actually registers — heavy-maintenance-lease-held, heavy-maintenance-backpressure, heavy-maintenance-yield-to-waiter — and each row's supporting field is chosen BY CAUSE (a lease hold names an owner, a backpressure conflict names a task). Frame 3 splits into the two producer states it had conflated: a missing holder with readable breaches is degraded; unknown is the no-readable-breach case, and it still says two entries are unreadable. Why no bar on the starved rows. The receipt has no below-threshold phase: a breach exists only past degradeAfterMs, so a track "filling toward the line" would never be observed, and a full track past the line reads as 100% — completion, which a wait is not. The pane's bar and the reducer's makeProgress also clamp done to total; the text is unclamped by construction.

Where the causes come from. Only the three contention classes register a waiter (MaintenanceBackpressureService.recordDeferral: lease-held, backpressure, yield-to-waiter); a shed window or a dependency gate is policy, not competition, and never reaches the ledger. The 2026-09-04 evening ledger still carried golden-path-* codes written before that boundary — the sketch renders the reachable set, and an older code arriving on the wire renders as its raw code in the same cell, unlabeled.

Rules folded from the peer input

  1. Wait as text, unclamped. waiting 11 h 45 min · threshold 60 min in the detail role, tabular digits; no <progress>, no bar, no marker (a marker on a full track re-imports the completion reading the text was chosen to avoid).
  2. State word starved in the wedged ink — the receipt's posture, not a diagnosis of the holder; unanchored for the backup lane.
  3. The lease is a section fact (fm-tasks-section-meta): holder · status · posture · the watchdog's checkedAt · threshold (degradeAfterMs, the plane's own value). No "since": the receipt has no acquisition time.
  4. Each row's own cause: a short label from reasonCode plus the field that cause carries — leaseOwner for a lease hold, blockingTaskName for backpressure and a yield; the raw code rides the cell's title. The check-time holder never explains a waiter.
  5. Motion on a new stamp only; the section's capture time may advance while the queue stands still (Frame 2).
  6. Cap per section: the count line keeps starved, unreadable, known and shown distinct under the Queued head — "known" is the pre-cap total the pane could read, never a claim to be the whole scheduler queue; blocked rows first as display order, never scheduler order.
  7. Posture is the watchdog's precedence: any readable breach → degraded; none readable but unreadable entries → unknown, said with the count (Frame 3a / 3b).

Tokens consumed, nothing minted

  • Type — chrome for section labels, body for names, detail for the wait and the lease line, micro for time, state, cause and pills. No display role: nothing here is an identity.
  • Color — the wedged ink for starved / unanchored / a degraded posture, the idle amber only for unknown posture; the signal ink stays on the existing progress bars. No new state color.
  • Rhythm — the pane's own: row gap space-2, section gap space-3, row padding space-2/space-3, the pill geometry.
  • Motion — the card's state-change transition on an observed change; prefers-reduced-motion removes it.

Names, enums, durations and timestamps only. An older Brain sends none of it; the pane then shows no starvation rows and no lease line, and counts only what it can see.

Deliberately absent

  • A progress kind for waiting. Rejected on the receipt's shape and the clamp.
  • A threshold marker. Offered by both peers as optional; rejected — see Frame 1's note.
  • "Since" on the holder, an ETA, "wedged". None is in the receipt.
  • Verbs. No release, no cancel, no re-run.
  • Priority-zero / bootstrap-critical pills. Both false across the fixture; the pill exists in the vocabulary and appears only when a receipt sets the flag.
