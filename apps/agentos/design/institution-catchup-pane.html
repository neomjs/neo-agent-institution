The design job is HIERARCHY: today the window receipt, the source states, the coverage facts and the citations all render at one visual weight as appended "·"-chained text. The contract below gives each fact its tier — the window is the headline, freshness is metadata pills, citations are receipt rows — and states the #24 target primitive with its section shape.

The hierarchy, stated: the window receipt is the pane's ONE display-tier line (it answers the pane's title); partition scope rides it as a pill, never a suffix. Source sections are chrome-tier headers with the state as a §04 family chip (mark + word — never hue-alone). Freshness is a metadata pill group — generated-instant, coverage fraction, manifest hash — each pill one fact with the value in ink; a degraded coverage fraction carries the warn tone on the WHOLE pill (border + text, two channels). The synthesis is the one body-tier prose block at 68ch; fallbacks render the same block dimmed with their reason on its own detail-tier line. Citations are receipt ROWS (kind · id · flags), mono detail-tier — they read as a ledger, not as prose.

target primitive · the #24 coordinate this contract binds

Primitive call: Neo.list.Base with useHeaders section records — the tasks-pane shape, not grid.Container. #24's primitive map names grid for catch-up as direction "refined per leaf"; this contract records the refinement: the pane renders exactly TWO fixed sections whose rows are heterogeneous (freshness pills, one prose block, N citation rows, one overflow line) with no column semantics, no sort/filter need, and a hard citation bound (citationLimit) — buffered rendering has nothing to buffer, and a column grid would force prose into cells. The flattened store shape: [sectionHeader(memory), freshness, synthesis, citation×N, overflow?, sectionHeader(prs), …] — one record type per row class, the list item renderer keyed by record.kind. The window/partition/actions chrome above the list stays pane composition (it is chrome, not data). Implementation coordinate: the #24 catch-up migration leaf consumes this contract; the existing CatchUpEntries store already models source records and extends to the flattened row classes.

What the landed anatomy already covers (absorbed, per the ticket): partition chips, the first-use choice, per-source honest states, citation bounds + census flags, the mark receipt — all landed through #17219/#17340-era work and preserved here. What the migration must add: the three-tier hierarchy (window headline / freshness pills / receipt rows), the §04 chip family on the state markers, the warn-toned coverage pill, and the list.Base section structure replacing the nested-container cards.
